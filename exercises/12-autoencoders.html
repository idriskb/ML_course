Exercises: autoencoders

Practice for Chapter 12. An autoencoder has an encoder $g_\phi : \R^p \to \R^k$ and a decoder $h_\psi : \R^k \to \R^p$, and minimises the reconstruction error $J = \frac1n\sum_i\norm{\bx_i - h_\psi(g_\phi(\bx_i))}^2$ on unlabelled data $\bx_1, \dots, \bx_n$. Every exercise is followed by a collapsed solution: try the question first, then reveal the solution one step at a time.

What you will practise

  • Encoding and reconstructing points by hand, and computing the reconstruction error.
  • Relating linear autoencoders to PCA through the eigenvalues of the covariance matrix.
  • Counting parameters and choosing the code size from a validation curve.
  • Using reconstruction errors for denoising and anomaly detection.
  • Recognising when a non-linear autoencoder can beat PCA, and what it cannot do.

Core conceptual questions

  1. An autoencoder is trained to output its own input. What is the "label" of each training point, and why is this called unsupervised learning?
  2. Why must the code size $k$ be smaller than $p$ for a plain autoencoder? What would a network with $k \ge p$ be able to learn?
  3. After training, which part of the network is usually kept, and what is it used for?
Solution

Step 1: (a) no labels. The target of $\bx_i$ is $\bx_i$ itself, so only the inputs are needed. Nobody has to annotate the data, which is why autoencoders can use large unlabelled datasets. The goal is not to predict a quantity but to discover structure: a short description $\bz$ from which $\bx$ can be rebuilt.

Step 2: (b) the bottleneck. With $k \ge p$ the encoder can copy $\bx$ into the code and the decoder can copy it back: the identity map achieves $J = 0$ and has learned nothing about the data. With $k \lt p$ the identity is impossible, so the network must keep the directions (or the curved coordinates) along which the data vary most and discard the rest.

Step 3: (c) what is kept. Usually the encoder: it maps each input to its code $\bz = g_\phi(\bx) \in \R^k$, a compressed representation used for visualisation ($k = 2$), as features for a later model, or for compression. The full network is kept when the reconstruction itself is needed, as in denoising and anomaly detection.

  1. What does a linear autoencoder (no activations) learn on centred data?
  2. Does it learn the principal directions themselves? Explain.
  3. What changes when the encoder and decoder are non-linear? What do we lose compared with PCA?
Solution

Step 1: (a) the PCA subspace. A linear autoencoder reconstructs $\hat\bx = DE\bx$, a point in the $k$-dimensional subspace spanned by the columns of $D$. Its smallest possible error is $$\lambda_{k+1} + \dots + \lambda_p,$$ the PCA error, reached when the reconstructions are the projections onto the span of the first $k$ principal directions.

Step 2: (b) not the directions themselves. If $E$ and $D$ are optimal, so are $AE$ and $DA^{-1}$ for any invertible $k \times k$ matrix $A$, because $DA^{-1}AE = DE$. The subspace is the PCA subspace, but the codes are any invertible linear transformation of the PCA scores: rotated, stretched, correlated. Gradient descent has no reason to pick the principal axes.

Step 3: (c) non-linear autoencoders. The set of reconstructions becomes a curved $k$-dimensional surface, which can follow data lying near a curve or a curved sheet, and the error can fall well below PCA's. The price: no closed form (iterative, non-convex training that depends on the initialisation), more hyperparameters, possible memorisation of the training set, and codes whose coordinates have no fixed meaning or order, unlike the ordered, uncorrelated principal components.

Explain the idea behind each use: (a) a denoising autoencoder; (b) anomaly detection with the reconstruction error; (c) using the encoder as features for a classifier trained on few labels.

Solution

Step 1: (a) denoising. The network receives a corrupted copy $\tilde\bx$ but must output the clean $\bx$. Copying the input no longer works, even without a bottleneck, because input and target differ. To remove the corruption the network has to learn what typical inputs look like and pull corrupted ones back towards them.

Step 2: (b) anomalies. Trained only on normal data, the bottleneck keeps the structure of normal inputs. A normal input is reconstructed well. An unusual input does not fit that structure, so its reconstruction is pulled towards something normal and the error $\norm{\bx - \hat\bx}^2$ is large. Flag inputs whose error exceeds a threshold set on normal validation data.

Step 3: (c) feature learning. Unlabelled data are often plentiful, labels scarce. The autoencoder learns, from all the unlabelled data, a code that keeps the main structure of the inputs. A simple classifier (for example logistic regression) on these few-dimensional codes needs far fewer labelled examples than one on the raw $p$ features, because it has far fewer parameters to estimate.

Intermediate exercises

A linear autoencoder on $\R^2$ with code size $k = 1$ has encoder $z = \bu\T\bx$ and decoder $\hat\bx = \bu z$, with $\bu = \frac{1}{\sqrt2}(1, 1)$.

  1. Encode and reconstruct the points $(2, 2)$, $(1, 3)$ and $(3, -1)$.
  2. Compute each squared reconstruction error and their mean $J$.
  3. Describe geometrically what the autoencoder does.
  4. Replace the encoder by $z = 2\bu\T\bx$ and the decoder by $\hat\bx = \frac12\bu z$. Compute the new code and reconstruction of $(1, 3)$. What does this show?
Solution

Step 1: (a) codes and reconstructions. $z = (x_1 + x_2)/\sqrt2$ and $\hat\bx = \frac{z}{\sqrt2}(1, 1) = \frac{x_1 + x_2}{2}(1, 1)$:

$\bx$$z$$\hat\bx$$\norm{\bx - \hat\bx}^2$
$(2, 2)$$4/\sqrt2 \approx 2.83$$(2, 2)$$0$
$(1, 3)$$4/\sqrt2 \approx 2.83$$(2, 2)$$1 + 1 = 2$
$(3, -1)$$2/\sqrt2 \approx 1.41$$(1, 1)$$4 + 4 = 8$

Step 2: (b) the mean error. $$J = \frac{0 + 2 + 8}{3} = \frac{10}{3} \approx 3.33 .$$

Step 3: (c) geometry. $\hat\bx = \bu\bu\T\bx$ is the orthogonal projection onto the line $x_1 = x_2$. Points on the line, like $(2, 2)$, are reconstructed exactly; the error is the squared distance to the line. $(1, 3)$ and $(2, 2)$ get the same code: the autoencoder cannot tell them apart.

Step 4: (d) a rescaled code. For $(1, 3)$, $z = 2 \cdot 4/\sqrt2 \approx 5.66$, twice the old code, and $$\hat\bx = \tfrac12\bu z = \tfrac12 \cdot \tfrac{1}{\sqrt2} \cdot \tfrac{8}{\sqrt2}\,(1, 1) = (2, 2),$$ the same reconstruction. Any rescaling of the code can be undone by the decoder, so the reconstruction error cannot fix the scale (or, for $k \ge 2$, the rotation) of the code.

For the $8 \times 8$ digits ($p = 64$), an autoencoder has encoder $64 \to 16 \to 4$ and a mirror decoder $4 \to 16 \to 64$, all layers with biases.

  1. Count the parameters of each of the four layers and the total.
  2. How many numbers does PCA with $k = 4$ store (directions and mean)?
  3. Each image is stored as its code. By what factor is the dataset compressed? What else must be kept to decompress it?
Solution

Step 1: (a) layer by layer. A layer $n_{\rm in} \to n_{\rm out}$ has $n_{\rm out}(n_{\rm in} + 1)$ parameters: $$16 \cdot 65 + 4 \cdot 17 + 16 \cdot 5 + 64 \cdot 17 = 1040 + 68 + 80 + 1088 = 2276 .$$

Step 2: (b) PCA. Four directions in $\R^{64}$ and the mean vector: $$4 \times 64 + 64 = 320 .$$ The autoencoder has about seven times as many parameters.

Step 3: (c) compression. Each image goes from 64 numbers to 4, a factor of $$\frac{64}{4} = 16 .$$ To decompress, the decoder (its $80 + 1088 = 1168$ parameters) must be kept as well; for PCA, the 320 numbers above. For a large dataset this fixed cost is small compared with the savings.

Centred data in $\R^5$ have covariance eigenvalues $\lambda = (5,\ 2,\ 0.6,\ 0.3,\ 0.1)$.

  1. What is the smallest reconstruction error a linear autoencoder can reach with $k = 1, 2, 3, 4$?
  2. What fraction of the variance does each $k$ keep? Which $k$ is the smallest that keeps at least $90\%$?
  3. A non-linear autoencoder with $k = 2$ reaches a validation error of $0.5$. Is this possible? What does it tell you about the data?
Solution

Step 1: (a) the linear optimum. The best linear autoencoder with code size $k$ reaches the PCA error $\lambda_{k+1} + \dots + \lambda_p$: $$k = 1:\ 3.0, \qquad k = 2:\ 1.0, \qquad k = 3:\ 0.4, \qquad k = 4:\ 0.1 .$$

Step 2: (b) variance kept. The total variance is $\tr\Sigma = 8$. The fractions kept are $$k = 1:\ \tfrac58 = 62.5\%, \qquad k = 2:\ \tfrac78 = 87.5\%, \qquad k = 3:\ \tfrac{7.6}{8} = 95\%, \qquad k = 4:\ 98.75\% .$$ The smallest $k$ with at least $90\%$ is $k = 3$.

Step 3: (c) beating PCA. Yes: a non-linear autoencoder is not limited to flat subspaces, so it can go below the linear bound of $1.0$ for $k = 2$. Reaching $0.5$ on validation data (not just training data) means the data lie near a curved two-dimensional surface that a plane cannot follow: two non-linear coordinates do almost as well as three linear ones ($0.4$).

Solution

Step 1: (a) decreases. From $k$ to $k + 1$: $$1 \to 2:\ 8.9, \qquad 2 \to 3:\ 4.8, \qquad 3 \to 4:\ 1.4, \qquad 4 \to 5:\ 0.5, \qquad 5 \to 6:\ 0.2 .$$

Step 2: (b) choose $k$. The gains are large up to $k = 3$, a clear drop at $k = 4$, and tiny afterwards: an elbow at $k = 3$ or $4$. $k = 4$ is a reasonable choice: it reaches $8.9$, within about $10\%$ of the best validation error, with half the code size of $k = 8$. For visualisation one would still use $k = 2$, accepting a larger error.

Step 3: (c) the gap. A larger code gives the network more freedom, so it can always reduce the training error, partly by memorising details of the training images. Those details do not carry over to new images, so the validation error stops improving. The growing gap ($8.1 - 4.9 = 3.2$ at $k = 8$ versus $0.5$ at $k = 1$) is the usual sign of overfitting; the code size is chosen on validation data, as $k$ in k-NN or the number of components in PCA.

A clean binary image has pixels $\bx = (1, 0, 1, 1)$. Masking noise sets its third pixel to 0, giving $\tilde\bx = (1, 0, 0, 1)$. A denoising autoencoder outputs $\hat\bx = (0.9,\ 0.2,\ 0.7,\ 1.0)$ for $\tilde\bx$.

  1. Compute the denoising loss $\norm{\bx - \hat\bx}^2$.
  2. Compute the loss of the identity map (output $= \tilde\bx$) on this example.
  3. Compute the loss a plain autoencoder would assign to the identity map, and explain why denoising prevents the network from learning the identity.
Solution

Step 1: (a) the denoising loss. The target is the clean image: $$\norm{\bx - \hat\bx}^2 = 0.1^2 + 0.2^2 + 0.3^2 + 0^2 = 0.01 + 0.04 + 0.09 = 0.14 .$$

Step 2: (b) the identity map. Outputting $\tilde\bx$ gives $$\norm{\bx - \tilde\bx}^2 = 0 + 0 + 1^2 + 0 = 1 .$$ The trained network does much better ($0.14$): it has partly restored the missing pixel (0.7 instead of 0), using what it learnt about typical images.

Step 3: (c) why the identity fails. A plain autoencoder compares the output with its own input, so the identity has loss 0 and is a perfect solution when $k \ge p$. In the denoising loss the input and the target differ, so the identity pays for every corrupted pixel, here a loss of 1. Because the corruption is drawn afresh at every step, the only way to keep the loss low is to learn the structure of clean images.

An autoencoder trained on normal transactions gives these reconstruction errors on 10 normal validation transactions: $$0.8,\ 1.1,\ 0.9,\ 1.4,\ 1.0,\ 1.2,\ 0.7,\ 2.1,\ 1.3,\ 1.0 .$$

  1. With the threshold $\tau = 1.5$, what fraction of normal validation transactions is flagged?
  2. Six test transactions have errors $0.9,\ 1.6,\ 1.2$ (normal) and $3.5,\ 1.4,\ 4.2$ (fraudulent). Which are flagged? Compute the precision and the recall for fraud.
  3. What happens to precision and recall if $\tau$ is raised to $2.5$? How would you choose $\tau$?
Solution

Step 1: (a) false-alarm rate. Only $2.1$ exceeds $1.5$, so $1/10 = 10\%$ of normal transactions are flagged. The threshold is the 90th percentile of the normal errors.

Step 2: (b) the test set. Flagged: $1.6$ (normal: a false alarm), $3.5$ and $4.2$ (fraud: caught). Missed: the fraud with error $1.4$. So $$\text{precision} = \frac{2}{3} \approx 0.67, \qquad \text{recall} = \frac{2}{3} \approx 0.67 .$$

Step 3: (c) a higher threshold. With $\tau = 2.5$ only $3.5$ and $4.2$ are flagged, both fraud: precision $2/2 = 1$, recall still $2/3$. A higher threshold gives fewer false alarms but, in general, more missed anomalies. $\tau$ is chosen from the cost of each error: the false-alarm rate one can afford sets a percentile of the normal validation errors (for example the 99th); if some labelled anomalies exist, compare precision and recall across thresholds, as with the threshold of a classifier in Chapter 4.

Challenging questions

The centred points $(3, 1)$, $(-3, -1)$, $(1, -1)$, $(-1, 1)$ are encoded with $k = 1$ by a linear autoencoder.

  1. Compute the covariance $\Sigma = \frac1n\sum_i\bx_i\bx_i\T$ and its eigenvalues.
  2. Using $J = \tr\Sigma - \bv\T\Sigma\bv$ for a unit vector $\bv$, compute the reconstruction error for $\bv = (1, 0)$ and $\bv = \frac{1}{\sqrt2}(1, 1)$.
  3. What is the smallest error any linear autoencoder with $k = 1$ can reach, and in which direction is the best line?
Solution

Step 1: (a) the covariance. Opposite points have the same $\bx\bx\T$: $$\Sigma = \frac14\Big(2\begin{pmatrix} 9 & 3 \\ 3 & 1 \end{pmatrix} + 2\begin{pmatrix} 1 & -1 \\ -1 & 1 \end{pmatrix}\Big) = \begin{pmatrix} 5 & 1 \\ 1 & 1 \end{pmatrix} .$$ With trace 6 and determinant 4, the eigenvalues solve $\lambda^2 - 6\lambda + 4 = 0$: $$\lambda = 3 \pm \sqrt5, \qquad \lambda_1 \approx 5.236, \quad \lambda_2 \approx 0.764 .$$

Step 2: (b) two directions. For $\bv = (1, 0)$, $\bv\T\Sigma\bv = 5$ and $J = 6 - 5 = 1$. For $\bv = \frac{1}{\sqrt2}(1, 1)$, $\bv\T\Sigma\bv = \frac12(5 + 1 + 2) = 4$ and $J = 6 - 4 = 2$. The horizontal line is much better than the diagonal.

Step 3: (c) the optimum. The smallest error is $$\lambda_2 = 3 - \sqrt5 \approx 0.764,$$ reached by the first eigenvector, $\bv_1 \propto (1,\ \lambda_1 - 5) \approx (0.973, 0.230)$, a line about $13^\circ$ above the horizontal. It is slightly better than $(1, 0)$ because it tilts towards the long axis of the points $\pm(3, 1)$. No linear autoencoder with $k = 1$ can do better, whatever its $E$ and $D$.

Data points lie uniformly on the unit circle $x_1^2 + x_2^2 = 1$ (centred, covariance $\frac12 I$).

  1. What is the smallest reconstruction error of PCA (or any linear autoencoder) with $k = 1$? Why is no line better than another?
  2. Give an encoder and decoder with $k = 1$ that reconstruct every point exactly.
  3. Your encoder in (b) must jump somewhere on the circle. Explain why a continuous encoder from the circle to $\R$ cannot give every point a different code, and what a trained (continuous) autoencoder does as a result.
Solution

Step 1: (a) PCA. $\Sigma = \frac12 I$ has $\lambda_1 = \lambda_2 = \frac12$, so the best error is $\lambda_2 = 0.5$. Every unit vector $\bv$ gives $\bv\T\Sigma\bv = \frac12$: the circle looks the same in every direction, so all lines are equally good, and equally bad: they keep only half of the variance.

Step 2: (b) a perfect code. Use the angle: encoder $z = \theta \in [0, 2\pi)$, the angle of $\bx$ (so $\bx = (\cos\theta, \sin\theta)$), and decoder $h(z) = (\cos z, \sin z)$. Then $h(g(\bx)) = \bx$ for every point on the circle: error 0 with a one-number code. The circle is one-dimensional, but curved.

Step 3: (c) the cut. The angle jumps from almost $2\pi$ back to $0$ at the point $(1, 0)$. A continuous encoder $g$ cannot avoid this: going once around the circle, $g$ starts and ends at the same value, so on that closed loop it rises and falls, and (by the intermediate value theorem) two different points on opposite sides of its maximum get the same code. Their reconstructions must then be the same point. A trained network (continuous, since it is built from continuous activations) therefore reconstructs most of the circle well but folds or cuts it somewhere, with a large error in a small region. Its error is far below $0.5$ but not zero.

You have $50\,000$ unlabelled $8 \times 8$ digit images and only $200$ labelled ones. Design an experiment to test whether autoencoder features help a classifier. Say which models you compare, what is fitted on which data, how hyperparameters are chosen, and what you report.

Solution

Step 1: split the labelled data. Set aside a test set from the labelled images (say 50), never used for any choice. The remaining 150 labelled images are used for training and cross-validation.

Step 2: learn the features without labels. Train the autoencoder on the $50\,000$ unlabelled images (with a held-out part of them to choose the code size $k$ and to apply early stopping). Fit PCA on the same unlabelled images for a fair comparison.

Step 3: the models compared. (i) Logistic regression on the raw 64 pixels; (ii) logistic regression on the PCA scores; (iii) logistic regression on the autoencoder codes $g_\phi(\bx)$. The encoders are frozen; only the classifier is trained on the 150 labelled images. Its regularisation strength (and $k$, if not fixed in Step 2) is chosen by stratified cross-validation on those 150 images.

Step 4: report. Refit each chosen model on all 150 images and report its test accuracy and confusion matrix, with the cross-validation scores and their spread. Since 50 test images give a noisy estimate, repeat with several random splits. The autoencoder features help if they beat both the raw pixels and PCA consistently; a natural follow-up is to vary the number of labelled images and see where the advantage disappears.
